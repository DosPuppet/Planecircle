## 2. Debt

- **Dead field:** `TurnLogQuery.bendKind` is read by `turnlog.ts` but produced by no card or by the engine. To be removed, with the `TurnLogQuery` ceiling.
- **Internal fields, not dead:** `againstYou` (TurnLogQuery, set by `stack.ts` for "attacked you"), `ofPlayers` (TargetSpec, set by `concreteSpec`), `sourceDefIs` (shield), `onceKey`, `copyOf`, `prepared`. ## 5. Second pass (reviews rerun on a smaller scale)

**Uncounted debt.** The guard (`debt.test.ts`) had two blind spots since its creation:
- a key written with the value `undefined` counted as used: `toCardDef` (`scryfall.ts`) and `activated()` (`dsl.ts`) copy all the options, so that 28 keys specific to one card seemed used by thousands of cards;
- keys declared away from the start of a line (union variant written on one line, nested object) were not read: 32 keys specific to one card.

Fixed: the guard ignores `undefined` values and reads any key after `{`, `;` or `,`. It now counts **114 keys specific to one card** (the 54 of the PLAN-H summary, plus 60 entered in the baseline with their card). The ceilings, measured another way (`members()`), were not affected.

Still outside the guard, to be decided:
- union variants specific to one card: 40 (Condition 12, Amount 7, Ref 6, TriggerSpec 15), to be tracked like the ops;
- string values specific to one card (about 138, for example `attached: "toHost"`, `spellFate.fate: "rebound"`): noisier, better tracked by a capped number than by a list;
- 19 keys specific to one card hidden behind a name shared with another meaning (`ObjectFilter.crew`, `TurnLogQuery.loyalty`, `CardDef.waterbend: 5`...); the guard counts by name and cannot see them.

**Checked 2026-10-09 (PLAN-J, `docs/plans/PLAN-J.md`).** Four claims of the "Merges that already have a generic form" paragraph above do not hold:
- `sourceDealtDamage` and `sourceDealtCombatDamage` model "hasn't dealt (combat) damage yet", which lasts the object's whole life, and `opponentDealtNoncombatDamageLastTurn` is already a snapshot of the previous turn: the turn log is cleared at each turn start (`turn.ts`), so none of them can be read from it (the two first ones merge with each other instead, `combat` flag);
- `prime` cannot go to `FilterCompare`, whose operands are characteristics of an object (power, toughness, mana value), not a count of lands; `evenCounters` has an exact form built from `countersOn`, `div` and `sum` instead;
- `untappedInUntapStep` cannot go to the turn log as it stands (the log has no untap entry): The Millennium Calendar becomes a batched `untaps` trigger instead;
- `while: "sourceTapped"` and `"tapped"` have no equivalent among the neighboring `ModifyWhile` forms (`"source"` means "on the battlefield"); both stay.
