# History of Planecircle (MTGX)

Project history, condensed from the former `docs/historique.md`, from the finished plans (R, P4, C, D, S, G, A, E, H) and from the two archived audits (2026-09-29, 2026-09-30). Git keeps the French originals. CLAUDE.md keeps only the present state, the working rules and the pitfalls; what is still open is in `docs/backlog.md`; the audits that are still current are in `docs/audits/`.

Conventions used below: "rules N" is the value of `RULES_VERSION` (`engine/src/record.ts`) after a lot; a lot marked **[rules]** changes engine behavior and advances that version. "Golden games" are the fixed-seed replays of `tools/golden.ts`; "fuzz fingerprint" is the seed-independent hash printed by `tools/fuzz.ts`. A code comment that cites a plan and a lot ("PLAN-H, H3") refers to the sections below.

## 3. PLAN-R: remediation of the 2026-09-30 audit

**Goal and dates.** Written 2026-09-30 from the audit of section 5, executed the same day, archived 2026-10-01. Lots F1 to F3 (foundations), R0 to R8. User decision (2026-09-30): no new cards until the engine is secured and finalized. Ending state: `RULES_VERSION` = 19; leftover R1 (families E, H, I and shields 615.7) done on 2026-10-01 with TDM D and ECL D; R7 continues as PLAN-C C13.

**Foundations**
- **F1 (rules 1):** `RULES_VERSION`, `GameRecord.rules`, `checkpoints` (the `outcomeHash(s)` fingerprint every 25 decisions; a stable projection: turn, step, expected decision, life, poison, zones as `defId`, battlefield, stack; pure hash cyrb53); one id counter per prefix (before, one counter shared by objects, effects, triggers and player effects: one more effect shifted every later object and old recordings aimed at other objects). Server policy for a saved game: same version -> replay, a different fingerprint = `.bad`; other version -> resumed if all fingerprints match, else the room is closed cleanly (file kept as `.rules<N>`, message "Game interrupted by an engine update"). Replay viewer reads up to the first divergence with a banner. Golden games (`ai/test/golden.test.ts`, fixed-seed games, regenerated by `--update`).
- **F2: debt guard.** `cards/test/debt.test.ts` compares three lists to `cards/data/debt-baseline.json`: `PlayerStaticAbilityDef` fields, `Keyword` members that are not printed keywords, effect operations used by one card. It fails on a new entry and on a stale one: the ceiling can only go down.
- **F3: server hardening.** Protected `decodeURIComponent` (400), client address from `X-Real-IP` set by nginx, `Origin` whitelist, `/scry/` without query string, per-IP room cap, security headers in `deploy/nginx-planecircle.conf`.

**R0 quick fixes [rules 2 to 6]** (tests in `engine/test/audit.test.ts`): split second and special actions, protection from everything vs unpreventable damage, 704.5b, win/lose effects vs "can't lose", counters paid as a cost not doubled (generic `effectOnly` property of doublers), 506.4, error beyond 100 state-based-action passes; taxes paid by free spells, attack and block taxes cumulative, obligation to attack only toward a defender without a tax (`forcedAttacks`); cleanup 514.3a (`turn.cleanupAgain`); lifelink once per source and simultaneous damage batch (batch opened by the outermost `simultaneously()`); 603.6a simultaneous arrivals (additive approach: each arrival detected at once, then reviewed at the end of the batch); R0.6 info and finishing (poison displayed, revealed cards logged, abandon confirmed, French names in engine prompts).

**R4.0 [rules 7]:** `playerStatics(s, p, key)` is the single access to player statics (the key is mandatory: a condition may itself read a static, and evaluating all conditions looped forever, found by fuzz); 23 direct reads migrated; three deliberate reads of object statics remain (Aura or linked source: Grievous Wound, Valgavoth, Terror of the Peaks).

**R2 entering the battlefield, copies, layers [rules 8 to 14]**
- R2.1: `EntersContext` (`replacement.ts`) carries tapped, attacking (defender), counters, `mods`, haste, impending, applied before the arrival event by `moveWithSpec`, token creation, `copyToken` and spell resolution; 508.4 defender of an attacking token asked.
- R2.2: `copiedDefId` also sees a copy carried by an attached permanent's static (Assimilation Aegis); mana value seen by filters is that of what is copied (front face without copy, 712.8e); `applyEntersReplacements` reads the copied definition (a Clone of a planeswalker enters with loyalty); a copy of a permanent spell makes the entry choices and becomes a token that enters so.
- R2.3: `copyCandidates` and `auraHosts`; `moveTo` (reanimation, blink) asks these choices before any move, to the future controller; outside resolution an automatic choice documented; 303.4g an Aura with nothing to enchant stays in its zone.
- R2.4: layer 2: `GameObject.baseController`, timestamped control effects in `s.effects` (`addControlEffect`, `whileSource`, `whileControlledBy`), `syncControl` (up to 4 passes, leaves combat, idempotent: a new fuzz invariant); called at the end of control operations, in state-based actions, after cleanup and in `removePlayerObjects` (800.4a: effects and Auras of a player who left are ignored, what he still controls is exiled). `controlChanges` and `auraControl` removed.
- R2.5: 613.8 by fixed point: `computing` plus a `provisional` map (result of the previous pass); `collectStatics` separates what does not depend on layers (reused) from dependent statics (re-evaluated), signature compared, at most three layer applications; a condition is dependent only if it reads a permanent while being evaluated (read counter). First try lost 19.5 % (the view built for each counted permanent cost O(n)); view cache and precomputed equipped permanents brought the loss to zero. Layer 5 `addColors` ("in addition to its other colors"); 707.9b copiable copy exceptions.

**R1 replacements (616) [rules 11, partly]**: `modifiers.ts` (`AmountMod` with `add`, `times`, `atLeast`; `chooseReplacementOrder(base, mods, prefer)` tries all orders up to 5 replacements and keeps the best for the affected player: minimal damage and life loss, maximal gains, tokens and counters except harmful ones, maximal draw except beyond the library; replacements of the same kind commute and are not permuted). Decision: nothing can suspend in the middle of `dealDamage`, `changeCounters` or `gainLife`, so the engine chooses for the affected player (616.1: first 616.1a to d, then timestamp order if they commute), documented as `auto choice`; one function so a real `ChoiceRequest` can be plugged later. Damage, counters, life and draw go through it (`drawCards`, one draw event, all 11 draw sites; `drawBonus` removed, two Vnwxt stack). Artist's Talent + Twinflame Tyrant: 3 -> 8 damage; Yoshimaru + Doubling Season: 1 -> 4 counters. The generic `EventReplacementAbilityDef`, the conversion of flags and shields 615.7 were postponed (families E, H, I; shields done 2026-10-01 as `fx.shield`).

**R3 spell copies [rules 12]:** one mechanism, `StackItem.pendingChoices` (`stackChoices.ts`; purpose `stackChoice`): choices of an item already on the stack that `announceNext` poses before triggers and priority. A spell copy is a `cardCopy` object on the stack; a question per word "target" (intent `changeTarget`, original targets suggested, same number of targets), then the "targeted" event (ward, valiant; not heroic nor crime: a copy is not cast). No `autoOk` on new targets (the autopilot would have answered for the player outside full control); as on Arena the question is asked, original targets pre-filled. Division is a `divide` question asked as soon as the item goes on the stack (spell, activated or triggered ability with two or more targets), kept in `StackItem.division`; the share of a target that became illegal is lost. The AI tries by simulation each new target of a single-target copy.

**R5, R6, R7, R8**
- R5 [rules 17]: simultaneous blocks in multiplayer (`combat.pendingBlocks`, applied together by `commitBlocks`, hidden by `projectView` until all defenders declared); mulligans round by round (`declareMulligan`, `s.mulliganTaken`, `nextMulligan`; 103.5).
- R6 [rules 18]: mandatory loop declared a draw (104.4b): `declareLoopDraw` (`gameOver` with `reason: "loop"`); the three guards (`advance` 100,000 turns, state-based actions 100 passes, host 10,000 automatic decisions per turn) now declare a draw; `watchLoop` counts passes with a non-empty stack without other decision, takes the fingerprint (`outcomeHash`, moved to `fingerprint.ts`) beyond 20, declares a draw at the third repetition or beyond 2,000 passes. Found while looking for "unfinished" fuzz games: a trigger of an eliminated player stayed pending forever and cleanup gave priority endlessly; fixed (800.4a).
- R7 [rules 19] first pass: one rules-test file per partial extension (TDM 24 tests, WOE 17, SOS 25, ECL 14, TLA 18, SPM 15, MSH 19, TMT 16, HOB 16, MKM 15, BIG 16: 195 tests) checking Oracle text; `rulings.test.ts` (10 tests from official rulings: lifelink, copies, replacements, cleanup, multiple prowess, Tablet of Discovery); two more Oracle patterns. They found 7 gaps, fixed: `ref.eventObject` and the "if the source..." condition ignored last known information of a departed object (The Ooze created 0 Mutagen, Esoteric Duplicator copied nothing); `pumpAll` ignored "other" (Harvester of Misery gave itself -2/-2); Thorin, Mountain-king attached nothing (inverted `attach` arguments); multiple prowess merged into one (Thor Odinson); a land milled by Tablet of Discovery could not be played; its restricted {R}{R} never paid (the solver now takes, per source, the ability that produces the most).
- R8: interface (hold priority; `passMode`: "End turn" is a soft pass that returns control as soon as an opponent puts something on the stack, Shift+Enter / Shift+click a hard pass; settings kept in `localStorage`; `undoMana`: a land tapped only for {T}, without trigger, untaps with one click while its mana is in the pool, deliberately not an option of `legalActions` because the random AI would loop; alert before passing with floating mana; combat damage preview `combatPreview.ts`; deckbuilder search syntax `t:`, `o:`, `c:`, `mv`, `pow`, `tou`, `r:`, `s:`; accessibility basics) and AI P3 (determinization by seen cards only; "you may", small numbers and one-of-up-to-6 options tried by simulation; mulligan by colors; pool `meta` for the tournament). Tournament on meta decks, high vs medium: 66.8 % +/- 3.8 before, 65.0 % +/- 3.8 after (not significant).

**Deferred by PLAN-R, still deferred or since done:** see `docs/backlog.md` ("Deferred until a card requires it"). Done since: "must be blocked if able" obligations with 509.1c/d maximization (PLAN-C C4), the view of the player controlling another's turn (722, `view.ts`), "the next time" shields (615.7, `fx.shield`, TDM).

Bench decisions kept from the plan: performance target 5,000 decisions/s with at most 5 % loss, compared before and after with `git stash` on mains power (never against an old number); new fuzz invariants: simultaneity batch empty after every decision, `syncControl` idempotent, at most 3 layer passes, "chaos" mode refuses malformed answers to the new choices.

## 4. Audit of 2026-09-29 (condensed)

Read-only audit of `dev` at commit `41eea2f`. Key numbers: 86 commits, 17,600 engine lines in 36 files, 29,200 card-script lines, about 2,750 playable cards of 5,161 (53 %), 150 effect operations, 55 triggers, 87 player-static flags, about 430 rules tests, 126 documented approximations (+ 63 sub-entries), no CI. Strengths: pure deterministic engine run in four places (Web Worker, authoritative server, AI simulations, fuzz), strict engine/autopilot separation, exhaustive `legalActions` shared by UI, AI, autopilot and server, layers with version cache checked by fuzz, clean error contract (`RulesError` vs `Error`), hidden information treated seriously, Scryfall import with keyword deduction, unusual test culture.

Weaknesses and the roadmap that answered them:
- **Card-specific special cases accumulating** (fields named after a card in `PlayerState`, `TurnStats`, `turn`; 87 player-static flags; no general replacement framework; incomplete layers; about 150 comments naming a card). Answered by the debt guard (F2), PLAN-R R1/R2/R4, PLAN-S.
- **Card accuracy not proven** (`implemented = !!script || onlyKeywords(...)`; smoke test only checks the card can be played; rules tests named about 20 % of an extension). Answered by the Oracle <-> script audit, expectations deduced from Oracle text, per-extension rules tests (R7, C13, K lots).
- **Approximation clusters** (free cast pushed after resolution -> casting during resolution 608.2g; mana abilities through the stack -> 605.3b; automatic costs and choices -> `ChoiceRequest` with `suggested` + `autoOk`; cost paid at resolution).
- **Platform:** in-memory rooms (an update cut running games), duel only, no BO3 with sideboard, no replays, 6.3 MB bundle, tokens without image, little accessibility, no security headers, no CI.
- **AI:** determinization knew the real deck composition of the opponent (a small cheat), generic evaluation, ISMCTS at the root only; measured high vs medium 60.8 %, high vs high without ISMCTS 56.7 %.

Roadmap P0 to P4 and its outcome (all done 2026-09-29/30 except P3, done as R8):
- **P0:** (1) GitHub Actions CI (`.github/workflows/ci.yml`: `verify --ci` on each push, `verify --full` nightly); (2) casting during resolution 608.2g (intent `castNow`, effect `fx.castDuringResolution`; migrated Discover, Etali, Uldaros, Kaervek, rebound...); (3) general replacement framework (kept for PLAN-R R1); (4) automatic choices -> `ChoiceRequest` (crew, Fabricate, sacrifice, counters removed as cost, proliferate); (5) mana abilities with a complex cost handled by `solvePayment` as sources with a cost, without the stack. About 25 approximations lifted and three rules errors fixed on the way (Kaervek, Chandra, Darksteel Colossus with a finality counter, The Darkness Crystal with Rest in Peace).
- **P1:** Oracle <-> script verifier (`npm run coverage -- --audit`; two omissions fixed: Greenhouse Propagator, Magmatic Galleon), expectations deduced from Oracle (138 cards), turn event log replacing card-specific counters (seventeen `TurnStats` counters and eight `s.turn` fields removed; nine `PlayerState` fields moved to player effects), lots 0.15 to 0.21.
- **P2:** game recording (seed + decisions), resumed online games, export and replays (0.22), token images (0.23), split bundle + compression + cache + service worker (0.24), BO3 with sideboard (0.25).
- **P3:** honest determinization (R8).
- **P4:** the meta coverage decision (section 6).

## 5. Audit of 2026-09-30 (condensed)

Read-only audit of `master` at commit `23698dc`; rule gaps marked "(exec.)" were confirmed by playing the position in the engine. Key numbers: 114 commits, 19,400 engine lines (38 files), 32,100 card-script lines, 2,911 / 5,161 cards playable (56 %), 650 `it`/`test` calls, 171 effect operations, 96 `PlayerStaticAbilityDef` flags (up from 85 in two days), 17 `TurnStats` counters, 51 keywords (about 16 card-specific).

Findings (17 numbered gaps in section 3.1, all fixed by PLAN-R): cleanup without state-based actions or priority (514.3a, #1); lifelink once per damage assignment instead of per source (#2); attack obligation vs attack tax deadlock (508.1d, #3, blocking); spell copies keeping original targets and not triggering ward (707.10c, #4); free spells ignoring cost increases (#5); simultaneous arrivals (603.6a, #6); "enters as a copy" only for cast spells (614.1c, #7); 704.5b flag never reset (#8); split second blocking special actions (#9); win/lose effects ignoring "can't lose" (#10); protection from everything preventing unpreventable damage (#11); stale controller after two steals (#12); copiable values (707.2, 707.9b, #13); counters and types added after the enter event (614.1c, #14); divided damage at resolution (601.2d, #15); non-creature staying in combat (506.4, #16); attackers put onto the battlefield getting a defender automatically (508.4, #17). Structural gaps: no layer 2, no 613.8, printed characteristics in conditions, replacement ordering for damage/counters/life/draw, no shields (615.7), simultaneous blocks, blocking obligations without maximization, no draw on mandatory loops, mulligans per player, Auras put in play (303.4f), protection only "from everything". Design debt: flags per card (`cantBeBlockedByHumans`, `...NonSpirits`, `...Glimmers`...), card-named treatments (`hellkite`, `empowerJace`, `tripleTriad`...), about 790 engine lines (mostly comments) naming about 450 cards, `stack.ts` over 2,290 lines. Two server bugs (unencoded URL crash, spoofable `X-Forwarded-For`), no `Origin` check, no security headers, `/scry/` forwarding the query string. Interface gaps versus Arena (priority control, poison not displayed, reveal events ignored, auto choices, mana undo, combat preview, accessibility, search syntax) and AI gaps (determinization from the real remaining list, 24 of 30 choice intents answered by the engine's suggestion, mulligan only by land count, no multiplayer ISMCTS).

## 9. PLAN-S: DSL cleanup, ceilings, performance (2026-10-03/04)

**Context and choice.** The ceilings of `cards/data/debt-baseline.json` had only risen since C1 (Effect 178 variants / 670 fields, Amount 77 / 131, Condition 82 / 138, TriggerSpec 62 / 157, Ref 35 / 55, ObjectFilter 91 fields, CardDef 95, GameObject 71, StackItem 46, CostDef 37; `singleCardKeys` 109, `op` 42). The user chose unions first, then the most redundant interfaces; the "pay" family and the `CardDef` rework stayed optional; performance lots separate and measured. Work on branch `plan-s`, one commit per lot.

**Principles (still the house rules).**
1. Only true merges: a variant disappears because a generic form (existing or parameterized) covers it; no moving fields into a sub-object to lower a count; no replacing variant names by an `action: "..."` string without simplifying the evaluator.
2. Cards do not change: the DSL helpers (`fx`, `amount`, `cond`, `when`, `ref`) are the facade and produce the generic form; only raw literals are fixed by hand (search for `kind: "..."` and `on: "..."`).
3. A lot without rules change is proven identical: golden games replay as is and fuzz results at equal seed are identical (compare `test-results/verify/fuzz-batch.json` and `npm run fuzz` with the same seed); otherwise it is a [rules] lot.
4. A lot lowers the ceilings in the same commit (`npx tsx tools/debt-ceilings.ts --write "PLAN-S Sx: ..."`; `debt.test.ts` demands exact equality) and removes stale `singleCardKeys` and `op` entries.
